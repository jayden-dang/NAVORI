## Context

Ports (ROAD-17, PORTS) already scans the user's listening TCP ports, places each under a project and worktree, attributes Docker ports to containers and answers `ports.list` and `ports.open`; it runs its own 3 s / 30 s cadence off the panel flag (modules/ports/src/actor.rs:62-68). It has no way to stop anything: `PortsAction` has only `List` and `Open`, `navori-macos` has no signalling code, the `Containers` trait has only `running()`, and `CoreSnapshot` carries no Ports state. Nothing in the kernel, FFI or CLI reads `Risk`, so the first Destructive Action (`ports.kill`) has no gate anywhere (verified, rg over kernel, ffi, ipc, cli). The menu shows Awake as its own row with a Holding list grouped by project in Swift (`AwakeSubmenuState`).

The constraint that shapes the approach is that the only thing standing between a user (or a script) and a signal is what the request itself carries. A pid names a process only until it exits and is reused, a Docker entry's pid is the Docker backend, a process group can hold processes the user never saw, and nothing mechanical asks for approval before ROAD-37. So the design makes the Core re-establish identity and protection from a fresh read at stop time, makes the request carry exactly the targets shown, and never lets a selector or the Shell's view widen what is signalled (PSTOP-1.3, 1.5, 2.4).

The alternative this rules out is the Seed's literal shape, "kill by worktree or project" resolved inside the Core from the last published state: it would let a group stop widen after the user confirmed, would act on state up to 30 s old, and for a Docker row would signal Docker itself. A second ruled-out shape is a Swift-side join of Awake and Ports: it would put the rule that decides whether a destructive control is offered in Swift (ARCH-1) and make fail-closed untestable in Rust.

Spine relied on: ARCH-1 (logic in the Core), ARCH-2 (Swift crosses only through `navori-ffi`, bindings only in `CoreStore`), ARCH-3 (no Module reads another; the join is in `navori-ffi`), ARCH-4 (typed Action with Risk), ARCH-14 (profiles share nothing), ARCH-16 (no timer under 30 s while the menu is closed). ARCH-5 is not met for deliberate same-UID CLI/IPC callers until ROAD-37 (requirements header, PSTOP-1.17). Fresh feature-graph query (load-subgraph, 2026-11-04): 16 registered CODEs, `owns_coverage` 11/16 = 0.69 (PSTOP has no tasks.md yet), so "no other feature owns this" is not claimed; neighbors by term and path are PORTS (modules/ports/, `crates/ffi/`), AWAKE (`Features/Panel/`, Settings), MENU, KCONTRACT (`ports` is the panel-flag consumer), PROCS (`crates/macos/`) and ICON; no active observations. Reuse comes from reading the code, not from that list.

## Decisions

1. **The request names the exact targets** (Weigh, card 1). `kill` takes a selector and a list of `(pid, start_us)` / container-id targets; the selector is a consistency check, never an expansion (Weigh, card 2; PSTOP-1.2, 1.3). The Seed's three selector forms are kept (Lock).
2. **The Core decides from a fresh read at stop time**: a fresh scan plus a Docker list, through the code the periodic scan uses, and one `entry(pid)` per process target (PSTOP-1.5, 2.4, 3.1). Protection never comes from the request or the Shell's view (Weigh, card 2 and card 3).
3. **Signalling lives in `navori-macos` behind a `Signals` trait with a fake** (Weigh, interpret's scan; PSTOP-1.16). `getpgid` comes from the same trait, so `ProcEntry` and every `ProcessSource` implementor stay as they are. The process group is read with `libc::getpgid`, not from kinfo offsets (the scan derived offsets 564/576/612 from the SDK header and none is pinned by a test; `getpgid` is typed and testable). `agent-decided`.
4. **A leader's group is signalled only when it holds nothing the user did not confirm** (Weigh, card 4; the group-listener rule is `agent-decided`): leader, not Navori's group or an ancestor's, every other listener of that group is a confirmed, unprotected target and could be read; else the pid alone.
5. **The stop runs as its own task that holds the `Request` and answers it** (code: `Request::respond(self)` consumes the request, crates/kernel/src/module.rs:111; dispatch timeout 30 s, runtime.rs:308). The task replies once; the loop then emits the Event and starts a scan directly (not through the scheduler deadline, so KCONTRACT-4.9's 30 s gap cannot delay it). `agent-decided`: the loop, not the task, emits the Event, so the task needs no event-bus handle.
6. **One overall 25 s deadline; containers and processes stop concurrently** (`agent-decided`, Weigh card 5; PSTOP-1.11, 3.5).
7. **Containers stop through the Engine `stop` call without `t`** (Weigh, card 5). A new `Containers::stop(id)`; status 204/304/404 are mapped, never the body (PSTOP-3.4).
8. **The Running view is composed in `navori-ffi` as a pure function** over the Ports state and the Awake view (Weigh, card 3), and carries ready-to-send request JSON per project and per port, so Swift never assembles a wire shape (`agent-decided`: this keeps wire knowledge in Rust, ARCH-1).
9. **The checkout path is a new field on `Placement`** (the PORTS spec handed this to ROAD-18, port-discovery/requirements.md:163): `root: Option<PathBuf>`. The Running view's project path is the root of the worktree holding the project's oldest listener (`agent-decided`).
10. **A fixed protected set, no config key** (Weigh, card 2; PSTOP-2.5). The helper to protect is identified by exe path equal to `CoreConfig.helper_path`, which reaches `PortsEnv` as a new field (`agent-decided`).
11. **A listener missing from the fresh scan is `Stale`; a zombie counts as gone** (`agent-decided`, clarifies PSTOP-1.5: the Core cannot read its kind or placement, so it cannot check protection or selector; nothing is signalled). See "Upstream sync-back" below.
12. **Tracking agents off makes every project Unknown** (code: `AwakeTable::snapshot` publishes session Leases only while tracking is on, modules/awake/src/domain/table.rs:687; docs/agents/verify.md:156). `agent-decided`, clarifies PSTOP-4.4.
13. **Container databases are protected by image name, partly** (Weigh, interpret's finding 2): a container entry has `kind: Docker` (modules/ports/src/docker.rs:72), so the exe-name rule cannot see it; the Engine list reply already carries `Image`, and the same list of names (`postgres`, `mysql`, `mariadb`, `redis`, `valkey`, `mongo`; `agent-decided`) is applied to the image's repository name. Coverage is partial (an image referenced by id or a custom name is missed; interpret's read-only probe found `klynt-postgres` on `postgres:16-alpine` and `klynt-redis` on `redis:7-alpine` matched, `klynt-minio` is an id hash and is not a database), kept open as Open Question 4.
14. **`Stop all ports…` does not reach `Other`** (Weigh, card 6 revised after the design: `Other` has no Lease, so it is always idle once Awake is known, and its listeners are unplaced); `Other` keeps its own `Stop N` and child menu. Requirements 7.1, 7.2, 7.4 are amended.
15. **No ADR.** The accepted gap against ARCH-5 is reversible (ROAD-37 adds the gate and wraps this request unchanged) and is written in the requirements header; it is not a challenge to the invariant.

## Architecture

Vocabulary: **module**, **interface**, **implementation**, **seam**. Rung numbers are the reuse ladder (2 in this codebase, 4 platform, 5 installed dependency, 7 new).

### A. Signalling seam (`navori-macos`)

Satisfies: PSTOP-1.16
Reuse: rung 5 — `libc` 0.2.191 is already a dependency of `navori-macos` only (`kill`, `getpgid`, `getpgrp`, `proc_pidinfo` exist; no production use today, so this is the first signalling code). New trait and fake: rung 7 for the trait shape.
Respects: ARCH-2, ARCH-8 (fake feature)
Interface: `pub trait Signals: Send + Sync { fn own_pid(&self) -> i32; fn own_group(&self) -> i32; fn group_of(&self, pid: i32) -> Result<i32, ReadError>; fn send(&self, to: SignalTarget, signal: Signal) -> Result<(), SignalError>; }`, `pub enum SignalTarget { Process(i32), Group(i32) }`, `pub enum Signal { Term, Kill }`, `pub enum SignalError { Gone, Denied, Failed }`; `MacSignals::new()`; `fake::FakeSignals` with a record of `(SignalTarget, Signal)`, per-pid scripts (obey or ignore `Term`, exit a `FakeProcesses` entry on a signal, set a pid's group, fail with `Denied`) and a hook that runs just before a signal is recorded.
Depth: if `Signals` vanished, callers would need the four libc calls, their errno mapping and the rule that `Group(pgid)` is `kill(-pgid)`; the interface hides that behind two enums and four methods, and `FakeSignals` hides a scripted process table.
Locality: extend `crates/macos/src/lib.rs` (one `mod signals; pub use signals::*;`) and `fake/mod.rs`; leave `ProcessSource`, `ProcEntry`, `MacProcesses` and every implementor untouched.
Surface: no existing reader changes (new items). The workspace's `unsafe` rule is unchanged: all `unsafe` stays in this crate with `// SAFETY:` on the first line (PORTS-9.5).

`MacSignals::send` maps `ESRCH` to `Gone`, `EPERM` to `Denied`, anything else to `Failed`; `Group(pgid)` calls `kill(-pgid, sig)`. `group_of` is `getpgid(pid)` with the same mapping into `ReadError`.

### B. The `kill` Action and its request model (`modules/ports`)

Satisfies: PSTOP-1.1, PSTOP-1.2, PSTOP-1.3, PSTOP-1.4, PSTOP-1.17, PSTOP-1.18, PSTOP-2.5, PSTOP-2.6
Reuse: rung 2 — extends `PortsAction` (modules/ports/src/action.rs:7-41) the way `Open` does: a `schemars::JsonSchema` + serde variant, hand-written `risk()` and `catalog()` arms.
Respects: ARCH-4
Surface: readers of `PortsAction`: `modules/ports/src/actor.rs` (`on_request` match) → replace (the match gains the arm); `action.rs` `risk()`/`catalog()` → replace; docs/codebase/modules.md:50 → replace (lists the Module surface); port-discovery tests that match `PortsAction` → none exhaustive (the scan found only the two src files). The shared `ActionSpec.input_schema` is the schema of the whole enum, so `ports.list`'s and `ports.open`'s schema text gains the `kill` variant: `replace` (consumers read the schema as a whole; no reader pins its text, to be confirmed by the tasks' reference search).
Interface: `PortsAction::Kill { selector: Selector, targets: Vec<Target> }`; `enum Selector { Pid(i32), Worktree { project: String, worktree: String }, Project(Option<String>) }`; `enum Target { Process { pid: i32, start_us: u64 }, Container { id: String } }`; reply `KillReply { results: Vec<TargetResult> }`, `TargetResult { target: Target, result: Outcome, reason: Option<String> }`, `enum Outcome { Stopped, StoppedAlone, AlreadyGone, StillStopping, Stale, Protected, OutsideSelector, Failed }` (`reason` is a fixed sentence for `Failed`, `Protected`, `Stale`, `OutsideSelector`, `StillStopping`). `risk()` returns `Risk::Destructive` for `Kill` only. Wire example: `{"kill":{"selector":{"project":"klynt"},"targets":[{"process":{"pid":412,"start_us":1730000000000000}},{"container":{"id":"4f…"}}]}}`.
Depth: if the request model vanished, callers would need to know that a selector never adds targets, that a `pid` selector names exactly one process target (PSTOP-1.4) and that answers come per target in request order; the interface is two enums and one reply struct.
Locality: extend `action.rs`; `actor.rs` gains the `Kill` arm (section F). `PortsEnv` gains fields (section C). `NoConfig` stays (PSTOP-2.6, guard: no config key, file or table).

Validation (`Kill` is rejected as `ActionError::Invalid` before anything is read): empty `targets`; a `Pid` selector whose targets are not exactly one `Process` with that pid; a `Container` id that is not 1 to 64 hex digits (it goes into a request line, so this also stops request-line injection). A serde failure is `DispatchError::InvalidAction`, as today (crates/kernel/src/runtime.rs:29-40).

### C. Fresh read, identity and protection (`modules/ports/src/stop/resolve.rs`)

Satisfies: PSTOP-1.5, PSTOP-1.6, PSTOP-2.1, PSTOP-2.2, PSTOP-2.3, PSTOP-2.4, PSTOP-3.1, PSTOP-3.2, PSTOP-10.3
Reuse: rung 2 — the fresh read is `Scanner::scan` (scan.rs:58) followed by `with_docker` (actor.rs:207) on a blocking thread, the same two steps `start_scan` runs; `kind()` (kind.rs:18), `place_listener` (place.rs:9) and `ProcessSource::entry` are reused as they are. `is_docker_backend` (kind.rs:36) changes from `pub(crate)` to `pub`.
Respects: ARCH-1, ARCH-3
Security: THR-5 (docs/security/threat-model.md:29)
Surface: `PortsEnv` gains `signals: Arc<dyn Signals>` and `helper: Option<PathBuf>`: readers are the two struct-literal sites, `PortsEnv::mac` (lib.rs:49) and `Rig::opening` (tests/common/mod.rs:230) → replace both; `PortsEnv::mac(home)` gains a way to set the helper (`with_helper(path)`), and `crates/ffi/src/lib.rs:299` (`PortsEnv::mac(PathBuf::from(&config.home_dir))`) is the one production caller → replace. `kind.rs` visibility: no reader changes.
Interface: `fn resolve(fresh: &FreshRead, guard: &Guard, selector: &Selector, targets: &[Target]) -> Vec<Resolved>` where `FreshRead { scan: Scan, entries: Vec<PortEntry>, docker: DockerStatus }` (the result of the scan and `with_docker`, with `with_docker` made `pub(crate)`), `Resolved` is `Go(ProcessPlan | ContainerPlan)` or `Refused(Outcome, &'static str)`, and `ContainerPlan { id, ports: Vec<u16> }`; one shared predicate `pub fn stop_class(entry: &PortEntry, own_pid: i32, helper: Option<&Path>) -> StopClass { Free, GroupProtected, Never }` is used by `resolve` and by the Running view (section H), so the two cannot disagree on a case they can both see (a container entry whose `ContainerRef.image` names a database image is `GroupProtected`); `Guard::new(signals, source, helper)` holds the never-set (own pid, own group, ancestors by walking `entry(pid).ppid`, the helper path, the Docker backend).
Depth: if `resolve` vanished, callers would need the order of the checks (identity, then fresh-scan membership, then selector, then protection) and the rule that every verdict comes from the fresh read; the interface is one function from (fresh read, guard, request) to per-target verdicts, pure and testable with fakes.
Locality: new file under `modules/ports/src/stop/`; `scan.rs` and `place.rs` stay unchanged except visibility.

Order of checks for a process target (first hit wins): `entry(pid)`: `Gone` or a zombie → `AlreadyGone`; start time differs or `ruid` is not the current user's → `Stale` ("The process changed."); the pid is absent from the fresh scan's listeners → `Stale` ("The port closed.", so the user is not told it changed; decision 11); the fresh entry is the Docker backend, Navori's own pid, an ancestor, or the helper → `Protected` under every selector; `Database` or `System` kind under `Worktree` or `Project` → `Protected` (`Pid` allows it, PSTOP-2.2); under `Worktree`/`Project` the entry's project and worktree must equal the selector's → else `OutsideSelector`. For a container target, first: IF `fresh.docker` is `Unreadable` or the socket was absent THEN `Failed` ("Docker is not reachable", PSTOP-3.6; `with_docker` swallows the error into an empty list, so this must be tested before membership); then, absent from the fresh container list, not running, or no longer publishing a host port → `Stale`; placement from the same `attribute` pass is checked against the selector → `OutsideSelector`. `Worktree` requires a worktree; a project's worktree-less entries are addressed by the `Project` selector, which accepts targets of any worktree including none. A container entry is `Free` unless its image names a database (`GroupProtected`); it is stopped by the container path; only a `Docker` entry with `container: None` and a pid-targeted backend are `Never`. A request cannot carry a kind or a flag, so there is nothing to ignore (PSTOP-2.4); `Protected` is evaluated only on the fresh entry.

### D. Stopping one process (`modules/ports/src/stop/process.rs`)

Satisfies: PSTOP-1.7, PSTOP-1.8, PSTOP-1.9, PSTOP-1.10, PSTOP-10.4
Reuse: rung 2 — `tokio::time::sleep` (paused-clock friendly, as the cadence tests use), `ProcessSource::entry` for the identity check; signalling through section A.
Respects: ARCH-1
Security: THR-5
Interface: `async fn stop_process(plan: ProcessPlan, source: &dyn ProcessSource, signals: &dyn Signals) -> (Outcome, Option<&'static str>)`; `ProcessPlan { pid, start_us, reach: Reach }` with `enum Reach { Group, Alone }` decided before the first signal by `reach_for(plan, fresh, signals, guard)`.
Depth: if it vanished, callers would need the sequence SIGTERM, 3 s, identity re-check, SIGKILL, 1 s, final check, and the Group-versus-Alone rule; the interface hides all of it behind one call that returns one outcome.
Locality: new file; nothing else changes.

`reach_for` returns `Group(members)` only when `signals.group_of(pid) == pid`, that group is neither `signals.own_group()` nor the group of an ancestor, and every other listener in the fresh scan whose `group_of` equals `pid` is in the request's targets and not protected; if `group_of` fails for any fresh listener it returns `Alone` (PSTOP-1.8; `agent-decided`). The confirmed listeners of a group are planned together: the leader's plan carries them as `members`, only the leader signals, and each member's own answer comes from its own `entry()` check afterwards (gone or zombie → `Stopped`; still present → `Failed`), so a mate is never answered `AlreadyGone` because the leader's group signal got there first. Invisible to the Core: members of the group that hold no port, listeners the scan skipped (`Scan.skipped`), and processes spawned during the wait; the confirmation text promises ports, never processes (PSTOP-1.8 note).

Sequence: send `Term` to `Group(pid)` or `Process(pid)`; `ESRCH` → `AlreadyGone`; `EPERM` → `Failed`. Sleep 3 s. `entry(pid)`: `Gone`, a zombie or a different start time → `Stopped` (Group) or `StoppedAlone` (Alone). Still the same → send `Kill` with the same reach, sleep 1 s (`agent-decided`, PSTOP-1.10), `entry(pid)` again: gone → `Stopped`/`StoppedAlone`; still the same → `Failed` ("it is still running"). The reach is decided once. Named race windows (written in the spec's accepted limits beside the one PORTS-1.2 accepts): from `entry()` in `resolve` to the SIGTERM, and from the second `entry()` to the SIGKILL, in each a pid can be reused; `kill(2)` has no start-time argument. The code between the second `entry()` and `send(Kill)` has no await point, so a test's replace hook can only act before the check or after the signal. A group-mate that appears during the 3 s is the third window.

### E. Stopping one container (`modules/ports/src/infra/docker.rs`)

Satisfies: PSTOP-3.3, PSTOP-3.4, PSTOP-3.6, PSTOP-3.7, PSTOP-3.8, PSTOP-3.9
Reuse: rung 2 — the framing, head parsing and `Wiped` buffer of the list call (infra/docker.rs:100-200); `DockerError`'s fixed texts. The status check of `parse_head` (:157-159, rejects any status but 200) is factored into a function taking the accepted statuses.
Respects: ARCH-1
Security: THR-5
Surface: the `Containers` trait gains `fn stop(&self, id: &str) -> BoxFuture<'_, Result<Stopped, DockerError>>`; implementors `DockerSocket` and `FakeContainers` (tests/common/mod.rs:191) → replace (both gain the method; the fake gets its own reply script and call count). `parse_head`'s callers → replace (they pass `&[200]`). No reader of the list call changes: its request bytes, 2 s limit and 1 MiB cap stay (PSTOP-3.7 guard; tests/docker_client.rs pins the request bytes).
Interface: `enum Stopped { Stopped, AlreadyGone }`; `DockerSocket::stop` sends `POST /containers/{id}/stop HTTP/1.1\r\nHost: docker\r\nContent-Length: 0\r\nConnection: close\r\n\r\n` (no `t`: PSTOP-3.3), maps 204 → `Stopped`, 304 and 404 → `AlreadyGone`, any other status → `BadStatus(n)`; it reads and discards any body and never puts it in an error (PSTOP-3.4); it has no client limit of its own shorter than the request: the remaining budget of the 25 s request deadline (section F) is its time limit, which is longer than the list call's 2 s (PSTOP-3.7; the test observable: a stop reply delayed past 2 s still succeeds, and one delayed past the request deadline answers `StillStopping`). There is no separate 30 s limit. When the deadline cancels the future the caller reports `StillStopping`; that the daemon goes on stopping the container after the client drops the connection is expected but unverified here. A 204 or 304 reply carries no length, so the read ends on `Connection: close` as the existing framing does.
Depth: if `stop` vanished, callers would need the request line, `Content-Length: 0`, the id check, the three status meanings and the rule that a body is never surfaced; the interface is one method returning two success cases and the existing fixed-text error.
Locality: extend `infra/docker.rs`, `Containers`; the stop code logs nothing about a container's working directory or environment (PSTOP-3.8: only the fixed error texts reach a log, as today).

### F. Stop orchestration (`modules/ports/src/actor.rs`, `stop/mod.rs`)

Satisfies: PSTOP-1.11, PSTOP-1.12, PSTOP-1.13, PSTOP-1.14, PSTOP-1.15, PSTOP-1.19, PSTOP-1.20, PSTOP-3.5, PSTOP-10.2
Reuse: rung 2 — the `InFlight` abort-on-drop guard and `start_scan` (actor.rs:32-41, 174-194), `ModuleCtx::emit` (module.rs:160), `Request::respond`.
Respects: ARCH-1, ARCH-14, ARCH-16
Surface: `Ports::on_request` is a sync function without `&mut self` (actor.rs:161-172); the `Kill` arm cannot run there. Readers: the `ctx.recv()` arm of `run_loop` (actor.rs:104-157) → replace (it handles `Kill` before calling `on_request`); `tests/timing.rs`, `tests/open.rs`, `tests/scan.rs` read the loop's behavior for `List`/`Open`/cadence and stay as they are (guards PSTOP-1.18, 1.19).
Interface: `Kill` arm: `let guard = StopTask::spawn(request, env_clones)` stored in `stops: JoinSet<StopDone>` (a local of `run_loop`, aborted when the loop returns, so a stopped or restarted Module sends no further signal, PSTOP-1.13; an aborted task drops its `Request`, so the caller sees `DispatchError::Unavailable`). `StopDone { counts: [u32; 8] }` comes back over the join set: the loop emits one Event `ports.stopped` (`Severity::Info`, `Warn` if any `Failed`) whose summary gives counts per outcome and nothing else (PSTOP-1.15), then, if no scan is in flight, calls `start_scan(now)` and sets `deadline = Some(now + cadence)`, else sets `rescan_after = true` and leaves `deadline` alone, and the `finished` arm starts one more scan when it sees the flag (PSTOP-1.14; setting `deadline = Some(now)` instead would let a due timer replace and abort a running scan). A loop-local registry of in-flight targets answers a second request's overlapping target `StillStopping` instead of signalling twice.
Depth: if the orchestration vanished, callers would need the rules that a request is one task answered once, bounded by 25 s, concurrent across targets, never blocking `List`, `Open` or the cadence, and followed by one scan; the interface is the `Kill` request and its single reply.
Locality: extend `actor.rs` (the arm, the join set, the select branch) and add `stop/mod.rs`; scan, cadence and `on_request` for `List`/`Open` stay.

Task body, all inside one `tokio::time::timeout_at(arrival + 25 s, …)` where `arrival` is when the loop received the request (PSTOP-1.11): fresh read on `spawn_blocking` (a clone of the loop's `Arc<dyn ProcessSource>`, `Scanner::new(source, home)` with a new `HarnessMemo`, then `with_docker`; a stalled read is bounded by the same timeout, and every target then answers `Failed` ("the process list could not be read in time"), since nothing was signalled); `resolve`; for each `Go` plan start `stop_process` or `containers.stop(id)` into a `FuturesUnordered` (one stop per container however many ports: the plan is keyed by container id, PSTOP-3.3); targets still pending at the deadline answer `StillStopping`; replies in request order (`TargetResult` per request target, a `Refused` verdict carried as is); if Docker could not be reached every container target is `Failed` and processes proceed (PSTOP-3.6). The kill's 3 s and 1 s waits use `tokio::time::sleep`, so tests run on a paused clock (`FakeClock`, tests/common/mod.rs). Failure notes (accepted, written in the spec): a restart or stop of the Module aborts the stop tasks, so SIGTERM already sent is not followed by SIGKILL, no reply comes (the caller sees `Unavailable`) and no Event is emitted; queued requests survive a restart (module.rs:20-24), so a `kill` whose caller gave up can still run, which is safe because every target is re-read. No timer is started when no request is in flight (PSTOP-10.2); the Event and the profile's Journal are the running profile's only (PSTOP-1.20, ARCH-14).

### G. Checkout path on `Placement` and image on `ContainerRef` (`modules/ports`)
