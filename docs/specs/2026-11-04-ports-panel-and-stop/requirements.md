## 1. Stop exactly the listeners I name

**Story:** As the user, I want to dispatch `ports.kill` for listeners I was shown and get a result for each, so that their ports are freed and nothing I did not name is touched.

- **PSTOP-1.1** THE SYSTEM SHALL register on the Ports Module an Action `kill` with Risk `destructive`, a description written for people and LLMs, and a JSON schema (ARCH-4; Seed, docs/ARCHITECTURE.md:319-326).
- **PSTOP-1.2** THE SYSTEM SHALL accept a `kill` request made of a selector and a non-empty list of targets (Weigh, card 1: the exact targets travel with the request). The selector is `pid`, or `worktree` with a project and a worktree, or `project`; an absent project in a `project` selector means the no-project group `Other` (PORTS-2.3). A process target is (pid, start time); a container target is a container id. The selector keeps the Seed's three forms (agent-decided, over the peer's lean to drop the selector: the Seed's `ports.kill{pid|worktree|project}` is a Lock).
- **PSTOP-1.3** THE SYSTEM SHALL act only on the targets in the request and SHALL NOT add a process, container or port the request does not name, whatever the selector (Weigh, card 2 follow-up: a selector is a consistency check on the targets, never an expansion).
- **PSTOP-1.4** IF the target list is empty, a target is malformed, or a `pid` selector does not name exactly one process target THEN THE SYSTEM SHALL reject the request as invalid and signal nothing. *(Amended 2026-11-05, agent-made, supersedes the text above where they differ: `validate` also rejects, signalling nothing: a Process target with pid 1 or lower (and a `pid` selector naming 1 or lower), a target list longer than 256 (`agent-decided` cap, `MAX_TARGETS` in modules/ports/src/action.rs), and a container target whose id is not 1 to 64 hex digits. One predicate, `is_container_id` in modules/ports/src/infra/docker.rs, serves `validate` and the Docker stop; the stop answers its `BadId` error for any other id and never sends it to Docker.)*
- **PSTOP-1.5** WHEN a process target is handled THE SYSTEM SHALL read that pid again and, IF no such process exists, answer `AlreadyGone`; IF one exists whose start time differs from the target's, whose real UID is not the current user's, or which is no longer a listener in a fresh scan, answer `Stale`; and in both cases signal nothing (Weigh, card 1; integrations.md:28 "only processes of the current UID").
- **PSTOP-1.6** WHEN the selector is `worktree` or `project` THE SYSTEM SHALL check from the target's fresh read that it lies in the named worktree or project, and otherwise SHALL answer `OutsideSelector` for that target and signal nothing (Weigh, card 2).
- **PSTOP-1.7** WHEN a process target has passed PSTOP-1.5, PSTOP-1.6 and the protected rules of story 2 THE SYSTEM SHALL send SIGTERM, wait 3 seconds, check again that the same pid still has the same start time, and only then send SIGKILL (Lock: integrations.md:28). *(Amended 2026-11-05, agent-made, supersedes the text above where they differ: a group mate that is itself a target is answered from its own check (`member_outcome`: gone, a zombie or a different start time gives `Stopped`; still the same process gives `Failed` with `It is still running`), never from the leader's signals. The SIGTERM, 3 s, SIGKILL escalation belongs to the leader alone: if the leader is gone after the wait, no SIGKILL is sent to the group, so a mate that survived the SIGTERM answers `Failed` with `It is still running`.)*
- **PSTOP-1.8** THE SYSTEM SHALL signal a target's process group only when the target is its group's leader, the group is neither Navori's own nor that of one of its ancestors, every other listener found in that group is in the request's target list and not protected, and every such listener could be read; in every other case it SHALL signal the pid alone (Weigh, card 4: leader-only; the group-listener rule is agent-decided, from the peer's finding that a leader's group on this Mac held two unrelated listeners). *(Amended 2026-11-05, agent-made, supersedes the text above where they differ: a group signal (`kill` of the negative group id) reaches every member of the group, including processes that hold no port and were not named, such as a wrapper shell; only the listeners the Core can see are checked, and the confirmation names ports, never processes.)*
- **PSTOP-1.9** THE SYSTEM SHALL answer each process target with one of `Stopped` (gone, the group was signalled), `StoppedAlone` (gone, the pid alone was signalled), `AlreadyGone` (no such process at the re-read of PSTOP-1.5), `StillStopping`, `Stale`, `Protected`, `OutsideSelector` or `Failed` with a fixed sentence (Weigh, cards 4 and 5; the result names are agent-decided). *(Amended 2026-11-05, agent-made, supersedes the text above where they differ: `reason` is optional: `AlreadyGone`, `Stopped` and `StoppedAlone` carry none, and a refusal inside the Core is `Refused(Outcome, Option<sentence>)`. Fixed sentences added during the build, all in `reason` of modules/ports/src/stop/mod.rs: `Navori could not check what it must not stop` (GUARD_INCOMPLETE: the guard could not read an ancestor, so the request fails closed), `Navori could not read the process list` (the process source could not be opened), `The target could not be read in time` (see PSTOP-1.11) and `Navori did not send that container id to Docker` (BadId).)*
- **PSTOP-1.10** IF a signal is refused by the OS, or 1 second after SIGKILL the same pid still has the same start time (`agent-decided`: the 1 second, inside the deadline of PSTOP-1.11), THEN THE SYSTEM SHALL answer `Failed` for that target with a fixed sentence that names no path and no environment value, and SHALL go on with the others.
- **PSTOP-1.11** THE SYSTEM SHALL reply to a `kill` request once, after every target has an answer or when 25 seconds have passed since the request, answering `StillStopping` for any target not finished, with one answer per target in the request's order (`agent-decided`: the 25 s deadline, under the 30 s dispatch timeout at crates/kernel/src/runtime.rs:308). *(Amended 2026-11-05, agent-made, supersedes the text above where they differ: a target whose fresh read had not finished at the deadline answers `Failed` with `The target could not be read in time` (nothing was signalled for it); `StillStopping` is for targets whose stop had started and for the overlap of PSTOP-1.21.)*
- **PSTOP-1.12** WHILE a `kill` request is being carried out THE SYSTEM SHALL keep answering `ports.list` and `ports.open` and keep its scan cadence (`agent-decided`: the stop runs as its own task, as scans do).
- **PSTOP-1.13** IF the Ports Module stops or is restarted while a `kill` request is in flight THEN THE SYSTEM SHALL send no further signal for that request (`agent-decided`).
- **PSTOP-1.14** WHEN a `kill` request has been answered THE SYSTEM SHALL start a scan at once unless one is in flight, so that the next published state shows the result (`agent-decided`). *(Amended 2026-11-05, agent-made, supersedes the text above where they differ: this holds on the failure path too: when the process source cannot be opened, the request still ends with the Event of PSTOP-1.15 and a scan start (which publishes the problem). The first build replied on that path with neither; fixed in commit ef3b8a9.)*
- **PSTOP-1.15** WHEN a `kill` request has been answered THE SYSTEM SHALL emit one Event whose one-sentence summary gives the number of targets per answer and names no process, path or container (`agent-decided`). *(Amended 2026-11-05, agent-made, supersedes the text above where they differ: the Event is also emitted when the process source cannot be opened (every target `Failed`, severity warn); its payload is the eight per-outcome counters and nothing else.)*
- **PSTOP-1.16** THE SYSTEM SHALL keep every signalling and process-group call in `navori-macos` behind a trait with a fake, so that `unsafe` stays confined as PORTS-9.5 requires and no default test signals a real process (docs/standards/testing.md).
- **PSTOP-1.17** WHEN a valid `kill` request arrives from the CLI or the IPC socket THE SYSTEM SHALL carry it out without a further approval step, until ROAD-37 adds one (Weigh, card 1; ARCH-5 limit above). *(Amended 2026-11-05, agent-made, supersedes the text above where they differ: ARCH-5 stays unmet for a deliberate same-UID CLI or IPC caller until ROAD-37. ROAD-37 must land before the AI or MCP can see `ports.kill`; the roadmap is not edited here.)*
- **PSTOP-1.18** (guard) WHEN `ports.list` or `ports.open` is dispatched THE SYSTEM SHALL CONTINUE TO reply as PORTS-1.3, PORTS-6.1, PORTS-6.2 and PORTS-7.6 require, from the last published scan and without starting one.
- **PSTOP-1.19** (guard) WHEN the Ports Module runs THE SYSTEM SHALL CONTINUE TO scan every 3 s while the panel is open and every 30 s while it is closed, and the port scan SHALL CONTINUE TO meet the 50 ms `port_scan_ms` budget (modules/ports/tests/timing.rs; `cargo xtask perf`).
- **PSTOP-1.20** (guard) WHEN the dev and release profiles both run THE SYSTEM SHALL CONTINUE TO share no data, log or socket (ARCH-14), and a `kill` SHALL write its Event only to the running profile's Journal.
- **PSTOP-1.21** (`agent-decided`) WHEN a `kill` request names a target that a request still in flight has claimed (the same pid and start time, or the same container id) THE SYSTEM SHALL answer that target `StillStopping` with `It is still stopping` and send no second signal for it, and a target repeated inside one request SHALL get the answer of its first occurrence. A claim lasts until its request ends, a panicked stop task included. Known gap: a group mate that a second request names but the first only signalled with its leader is not claimed.
- **PSTOP-1.22** (`agent-decided`) THE SYSTEM SHALL log every signal sent (pid, start time, signal, scope `process` or `group`, result), every fallback from a group to the pid alone with a fixed reason, every refused target (a pid and start time, or a container id) and every container stop (id and result), and SHALL log no path, process name, container name or environment value.

## 2. Never stop what could hurt

**Story:** As the user, I want a group stop to leave databases, system services, Docker and Navori alone, so that pressing `Stop` is safe.

- **PSTOP-2.1** WHEN the selector is `worktree` or `project` THE SYSTEM SHALL answer `Protected` for a target whose fresh read has kind `Database` or `System`, or which is a container whose image name is a database image (`postgres`, `mysql`, `mariadb`, `redis`, `valkey`, `mongo`; the list is `agent-decided`, read from the `Image` of the Engine list reply, with no new request), and SHALL signal nothing for it (Weigh, card 2; the image rule is Weigh, interpret's finding 2 on the design). *(Amended 2026-11-05, agent-made, supersedes the text above where they differ: a container's image is published in `ports.list` and compared as its last path segment only (no registry, namespace, tag or digest; none for a bare image id), see PSTOP-2.7.)*
- **PSTOP-2.2** WHEN the selector is `pid` THE SYSTEM SHALL handle a `Database` or `System` target like any other (Weigh, card 2: the user pointed at that one process).
- **PSTOP-2.3** THE SYSTEM SHALL, under every selector, answer `Protected` and signal nothing for the Docker backend process (`com.docker.backend`), for Navori's own Core process, for any ancestor of it, and for the `navori` helper process (Weigh, card 2).
- **PSTOP-2.4** THE SYSTEM SHALL decide protection from the target's fresh read and SHALL NOT take a kind, a name or a flag from the request.
- **PSTOP-2.5** THE SYSTEM SHALL fix the protected set in code and SHALL NOT add a config key, file or table for it (`agent-decided`: a configurable list, which THR-5 names, needs a persisted format; it is a later ROAD).
- **PSTOP-2.6** (guard) WHEN the Ports Module reads its config THE SYSTEM SHALL CONTINUE TO use `NoConfig` and to accept the config files of today.
- **PSTOP-2.7** (`agent-decided`) THE SYSTEM SHALL publish a container's image in `ports.list` as the last path segment of its reference only, without registry, namespace, tag or digest, and none for a bare image id, so a private registry host never reaches the state.

## 3. Stop a container

**Story:** As the user, I want a project's containers stopped by the same press as its processes, so that a Compose project's ports are freed.

- **PSTOP-3.1** WHEN a container target is handled THE SYSTEM SHALL list the running containers again and go on only if one with that id is running and still publishes a port to the host, and otherwise SHALL answer `Stale` for that target (port-discovery/requirements.md:162; Weigh, card 5).
- **PSTOP-3.2** WHEN the selector is `worktree` or `project` THE SYSTEM SHALL check from the fresh read that the container lies in the named worktree or project, as PSTOP-1.6 does for a process.
- **PSTOP-3.3** THE SYSTEM SHALL send one Docker Engine `stop` request per container however many of its ports are listed, without a `t` value, so that the container's own stop timeout applies (Weigh, card 5).
- **PSTOP-3.4** THE SYSTEM SHALL answer a container target `Stopped` on a 204 reply, `AlreadyGone` on a 304 or 404 reply, `StillStopping` when the request deadline of PSTOP-1.11 ends first, and otherwise `Failed` with a fixed sentence that never repeats the daemon's reply text (Weigh, card 5).
- **PSTOP-3.5** THE SYSTEM SHALL carry out container stops and process stops of one request at the same time, inside the one deadline of PSTOP-1.11 (`agent-decided`).
- **PSTOP-3.6** IF Docker cannot be reached THEN THE SYSTEM SHALL answer every container target `Failed` and SHALL go on with the process targets.
- **PSTOP-3.7** (guard) WHEN the running containers are listed THE SYSTEM SHALL CONTINUE TO use the 2 second and 1 MiB limits of today, and the stop request SHALL have its own, longer time limit. *(Amended 2026-11-05, agent-made, supersedes the text above where they differ: the stop request has no client limit of its own; only the 25 s request deadline of PSTOP-1.11 bounds it. This replaces 'its own, longer time limit'.)*
- **PSTOP-3.8** (guard) WHEN a container is stopped THE SYSTEM SHALL CONTINUE TO write no container working directory and no container environment value to a log or an Event (PORTS-10.4).
- **PSTOP-3.9** THE SYSTEM SHALL send the Docker Engine no request other than the list of running containers and `stop`.
- **PSTOP-3.10** THE SYSTEM SHALL describe in the Docker row of docs/architecture/integrations.md that Navori writes to Docker only by stopping a container, in place of "Nothing is written to Docker".

## 5. Free a project's ports in two actions

**Story:** As the user, I want to hover an idle project, press `Stop 3` and confirm, so that its ports are freed in two actions. *(Amended 2026-11-05, operator decision: the `Stop N` capsule on the project row is removed as a duplicate of the child menu's `Stop N ports`; the story now reads hover a project to open its child, press `Stop N ports` and confirm.
