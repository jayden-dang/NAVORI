# 0007 — Public releases stay self-signed and are built by CI on a tag

Status: Accepted · 2026-11-04 · Amends 0004

ADR 0004 assumed one user building from source, so Gatekeeper never saw a quarantined download; once other people install Navori through a personal Homebrew tap (MILE-9, ROAD-27), every download is quarantined and a self-signed app is rejected. We keep the existing `Navori Local Signing` identity rather than pay for a Developer ID, because Keychain access and privacy grants are tied to it and must survive `brew upgrade`; the cask's `postflight` removes the quarantine flag and its caveats say the app is self-signed and not notarized, so users opt in through `brew trust` instead of clicking Open Anyway on every release. Releases are built, signed and published by GitHub Actions on a `v*` tag that must equal the workspace version, with the `.p12` and the tap token held only in a `release` Environment limited to `v*` tags, third-party actions pinned by SHA, and an offline backup of the `.p12`; the GOAL-11 perf gate cannot run on a shared runner, so `cargo xtask release-check` runs it locally before the tag is pushed. The cost is that anyone holding the `.p12` can ship an update macOS trusts as Navori, Gatekeeper is bypassed for Navori users, and `homebrew/cask` stays closed until a Developer ID and notarization replace this.
