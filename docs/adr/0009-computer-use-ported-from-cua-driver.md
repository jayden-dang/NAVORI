# 0009 — Computer use is built in navori-macos by porting cua-driver, structured paths first

Status: Accepted · 2026-11-05

Navori AI needs to operate other Mac apps without taking the user's cursor, focus or Space, and the working reference we found is cua-driver (trycua/cua, MIT, Rust), whose macOS crate is about 60k lines with about 633 `unsafe` sites, pins UniFFI `=0.31.0` against Navori's `0.32.2` and runs as its own daemon; Siri AI's developer preview (macOS 27.3, 2026-11-03) lets Siri call into an app that adopts App Intents, and no API for one app to invoke another's was found as of 2026-11-05, so it cannot be the engine. So computer use is Navori's own: the Actions, Risk levels and approvals belong to Navori, and the Accessibility tree reading, ScreenCaptureKit capture, SkyLight background input and focus guard are ported from cua-driver into `navori-macos` (ARCH-9) with its MIT notice kept beside the ported code, rather than embedding its daemon or rediscovering private-API behavior from nothing; this departs from P3's list of Swift-owned frameworks on purpose — the permission prompts and grant checks for Accessibility and Screen Recording stay in Swift, while the calls that read and drive other apps are low-level system FFI in Rust, because the logic choosing and running them is the Core's. Each request takes the cheapest Control path that works — Navori's own Actions and MCP tools, then other apps' App Intents through Shortcuts or AppleScript, then the Accessibility tree, then SkyLight background input, then screenshots with pixel clicks — because SkyLight is private API that any macOS release can break and Apple is tightening agent access (the Full Disk Access notice of 2026-10-02); cua-driver's AGPL `cua-perception` extension, its non-macOS platforms, browser CDP, cursor overlay and recording are not ported.
